# 법정경비 사용내역서 관리 프로그램 — 설계문서

- 작성일: 2026-09-03
- 대상 현장: 안양 인덕원 주변 도시개발사업 부지조성공사 (케이아이건설㈜, 발주 경기주택도시공사)
- 상태: 설계 승인 완료, 구현 계획 수립 대기

## 1. 문제

건설현장의 법정경비 사용내역서를 매월 4종 작성해 발주처에 제출한다. 현재는 사진이 포함된
29MB짜리 엑셀 매크로 통합문서를 **지난달 파일을 복사해 고쳐 쓰는 방식**으로 만든다.

이 방식이 실제로 만들어낸 문제를 받은 파일에서 직접 확인했다.

- **다른 현장 데이터 잔존**: 산업안전보건관리비 사진대지 캡션에 `경기도 광주 쌍동1지구 공동주택
  신축공사`(2021-06-26)가 그대로 남아 있다. 현재 현장과 무관한 내용이다.
- **다른 문서 데이터 잔존**: 안전관리비 Ⅱ의 내역서(상세) 인쇄영역 밖(L~R열)에 산업안전보건관리비
  쪽 내역(`신안종합철물`, `수평생명줄(웨빙/주황색)`, `보안경안전모`)과 연봉 `65,000,000`이 남아 있다.
- **깨진 수식**: 같은 시트에 `#REF!` 2건(Q16, L25). 인쇄영역 밖이라 출력에는 안 나오지만 시트를
  건드리면 표에 나타난다.
- **보이는 값과 인쇄되는 값의 불일치**: 집계표의 누계 공정율이 화면 셀(E5)은 0.57%인데 실제 제출된
  PDF는 0.36%(숨은 열 I5)다.
- **구조 불일치**: 안전관리비 Ⅱ는 항목이 2개인데 항목별 사진대지 시트는 5개다(Ⅰ에서 복사한 흔적).

제출본에 잘못된 현장명이나 잘못된 금액이 섞이는 것은 실무상 심각한 사고다. 이 프로그램의 존재
이유는 **작성 편의가 아니라 이런 사고를 구조적으로 불가능하게 만드는 것**이다.

## 2. 현행 분석 (실측)

### 2.1 문서 4종

말로는 3종이지만 실제 제출물은 4종이다. 서식 골격은 4종 모두 동일하다.

| 문서 | 항목 수 | 근거 법조문(집계표 하단 문구) | 서명란 |
|---|---|---|---|
| 산업안전보건관리비 사용내역서 | 9 | 건설업 산업안전보건관리비 계상 및 사용기준 제10조 제1항에 의거 위와 같이 사용내역을 제출합니다. | 작성자(안전 관리자) + 확인자(안전보건총괄책임자) |
| 안전관리비 사용내역서 Ⅰ | 5 | 건설기술진흥법 시행규칙 제60조에 의하여 위와 같이 사용내역을 제출합니다. | 확인자(안전보건총괄책임자) |

### 2.3 제출본 구성

공통 4장표 뒤에 사진대지와 증빙이 붙어 한 PDF로 병합된다.

| 문서 | 실제 제출본 페이지 |
|---|---|
| 산업안전보건관리비 (2026.07) | 4장표 + 사진대지 7장 = 11p |
| 환경보전비 (2026.08) | 4장표 + 전자세금계산서 1장 + 거래명세서 1장 = 6p |
| 안전관리비 Ⅰ / Ⅱ (2026.08) | 4장표 = 4p |

병합 순서: 갑지 → 집계표 → 항목별 사용내역 → 내역서(상세) → 사진대지 → 증빙

### 2.4 인쇄 설정 실측값

용지는 4종 전부 A4 세로(595.2 × 841.68 pt) 고정이다. 여백 단위는 인치.

| 장표 | 문서 | 배율 | 인쇄영역 | 여백 L/R/T/B |
|---|---|---|---|---|
| 갑지 | 4종 공통 | 92% | A1:L54 | 0.63 / 0.24 / 0.75 / 0.75 |
| 집계표 | 산안비 | 92% | A1:H26 | 0.31 / 0.31 / 0.75 / 0.55 |
| 집계표 | 안전Ⅰ·Ⅱ·환경 | 95% | A1:H25 | 0.31 / 0.31 / 0.75 / 0.55 |
| 항목월 | 산안비 | 91% | A1:H17 | 0.47 / 0.31 / 0.39 / 0.39 |
| 항목월 | 안전Ⅰ·Ⅱ·환경 | 97% | A1:H16 | 0.47 / 0.31 / 0.39 / 0.39 |
| 내역서(상세) | 산안비 | 75% | A1:K93 | 0.39 / 0.39 / 0.75 / 0.75 |
| 내역서(상세) | 안전Ⅰ | 75% | A1:K55 | 0.39 / 0.51 / 0.75 / 0.75 |
| 내역서(상세) | 안전Ⅱ | 93% | A1:K55 | 0.39 / 0.51 / 0.75 / 0.75 |
| 내역서(상세) | 환경 | 75% | A1:K36 | 0.39 / 0.51 / 0.75 / 0.75 |

**결론: 재현 대상은 16장이 아니라 장표 4종 + 문서별 설정값이다.** 갑지는 4종이 완전히 같고,
나머지는 `산안비 계열`과 `안전Ⅰ·Ⅱ·환경 계열`로 갈린다. 안전Ⅱ 내역서의 93%만 예외인데,
내용이 늘어나 손으로 배율을 줄인 흔적으로 판단한다.

### 2.5 글꼴

문서마다 다르다. 산안비는 **Pretendard** 계열, 안전Ⅱ·환경은 **맑은 고딕** 계열이 본문이고,
제목은 **HY헤드라인M**, 그 밖에 돋움·굴림·굴림체·경기천년제목·나눔바른고딕 옛한글·Tahoma가 섞여 있다.
크기는 6~24pt.

즉 현재 출력물은 하나의 서식이 아니라 손으로 조금씩 갈라진 파생본이다.

### 2.6 사진대지

- A4 1장 = 사진 2장
- 사진마다 캡션 4칸: 공사명 / 위치 / 내용 / 날짜
- 분량: 월 51~60장. 통합문서 29MB 중 28.6MB가 사진이다.

### 2.7 기타 서식 세부

- 금액 0은 `-`로 표기
- 계상액은 `₩203,126,000 원 (이억삼백일십이만육천원)` 형식 — **한글 금액 표기 자동 변환 필요**
- 항목별대비는 백분율 표기
- 작성일자 표기가 문서마다 다르다: 산안비는 날짜값(2026-08-31), 나머지 3종은 문자열
  (`2026년    8월   31일`) — 공백 배치까지 서식의 일부다

## 4. 접근안 비교와 결정

| | A안 엑셀 채우기 | **B안 자체 PDF 생성** | C안 엑셀+무료변환기 |
|---|---|---|---|
| 방식 | 기존 xlsm에 값을 넣고 Excel로 PDF 저장 | 서식을 프로그램 안에 재현해 PDF를 직접 그림 | openpyxl로 채우고 LibreOffice로 변환 |
| 육안 구분 불가 | 원본 그대로라 확실 | 재현 필요, 자동 검증으로 담보 | 렌더링 차이로 줄바꿈·글꼴 틀어짐 |
| Excel 의존 | 필수 | 없음 | 없음 |
| 페이지 자동 분할 | 행 삽입 시 서식 깨짐 잦음 | 완전 제어 | 불안정 |
| 사진 자동배치·축소 | 느리고 불안정 | 완전 제어 | 불안정 |
| 증빙 PDF 병합 | 별도 도구 필요 | 한 번에 | 별도 도구 필요 |
| 설치 없이 실행 | 불가(Excel 필요) | 가능 | 불가(LibreOffice 필요) |

**결정: B안.** "엑셀 완전 대체", "설치 없이 실행", "줄 늘려 여러 장", "사진 크기·화질 자동정리",
"증빙 병합", "발주처 다른 현장 대비" 여섯 조건이 모두 B안 쪽이다. A안은 Excel을 백그라운드로
돌리는 구조라 "엑셀을 더 이상 열지 않는다"는 목표와 정면으로 어긋나고, 월 30MB 사진을 다루면
자동화가 자주 멈춘다. C안은 정확도 기준을 못 맞출 위험이 크다.

**결정: 서식 통일은 하지 않는다(1차).** 문서마다 글꼴·배율이 다르지만 지금 모양 그대로 재현한다.
발주처가 매달 보던 문서가 갑자기 달라지는 것 자체가 반려 사유가 될 수 있다. 통일은 운영이
안정된 뒤에 다시 판단한다.

## 5. 데이터 구조

- **현장** (1건) — 업체명, 현장명, 소재지, 대표자, 발주자, 공사금액, 공사기간, 작성자/확인자
  직책·성명. **4종 문서가 공유한다.** 한 번 입력하면 모든 장표 머리말이 여기서 채워지므로,
  다른 현장 이름이 섞이는 사고가 구조적으로 불가능해진다.
- **경비 종류** (4종) — 고유한 항목 목록, 문서 제목, 근거 법조문 문구, 서명란 구성, 서식 설정값.
- **계상액 이력** — 종류별로 "언제부터 얼마". 설계변경이 나도 과거 제출본의 계상액은 유지된다.
- **월** — 종류 × 연월. 누계 공정율(수기), 상태(작성중 / 제출완료).
- **집행 내역** — 월·항목에 속한다. 일자, 회사명, 세부내역, 단위, 수량, 단가, 금액(공급가액), 비고.
  전월누계는 이전 월들에서 자동 계산한다. 착공~2026.08은 "개시 잔고" 한 줄로 입력한다.
- **증빙** — 집행 건에 붙는다. 원본 파일을 프로그램 폴더로 복사 보관한다.
- **사진** — 항목/집행 건에 붙는다. 원본과 인쇄용 축소본을 함께 보관한다. 캡션 4칸은 수기 입력.
- **제출 스냅샷** — 제출 확정 시점에 그 달 전체를 동결하고 생성된 PDF를 함께 보관한다.

| 보관함 | 과거 제출본 목록, 제출 당시 값 그대로 재출력 |

### 6.2 월 마감 7단계

1. 월 열기 — 전월누계 자동 승계
2. 내역 입력
3. 증빙·사진 첨부
4. **검증**
5. 미리보기
6. **제출 확정 (동결)**
7. PDF 생성·저장·인쇄

### 6.3 검증 규칙

현행 파일에서 실제로 발견된 사고들을 기준으로 정했다.

- 누계사용금액이 계상액을 초과
- 금액 ≠ 수량 × 단가
- 전월누계가 직전 달 마감값과 불일치
- 사진 캡션 4칸 중 빈칸
- **캡션의 공사명이 현장 설정과 다름** ← `경기도 광주 쌍동1지구` 유형 사고 차단
- 금액이 있는데 증빙이 첨부되지 않은 집행 건

제출 확정 시 해당 월이 잠긴다. 이후 계상액·공사금액이 바뀌어도 과거본은 그대로다. 수정이
필요하면 잠금을 해제하고 재확정하며, 그 사실이 이력에 남는다.

## 7. 출력 엔진과 정확도 검증

### 7.1 서식을 데이터로 분리

장표 4종의 칸 위치·선 굵기·글꼴·배율·여백을 **실측 치수표**로 두고, 문서 4종은 그 표를
참조하며 제목·항목 목록·근거 법조문·서명란만 교체한다. 발주처가 다른 현장을 맡으면 치수표를
한 벌 더 만들면 된다. 적용할 실측값은 2.4·2.5에 확보되어 있다.

### 7.2 렌더링 규칙

- 용지 A4 595.2 × 841.68 pt 고정
- 글꼴은 1차에서 현행 그대로 사용하고 **PDF에 임베딩**해 다른 PC에서도 틀어지지 않게 한다
- 표가 길어지면 머리행을 반복하며 다음 장으로 넘긴다
- 한 항목 블록이 페이지 경계에서 잘리지 않도록 묶어서 넘긴다
- 소계는 항상 해당 항목의 마지막 줄에 붙인다
- 금액 0은 `-`, 계상액은 한글 금액 병기
- 사진은 인쇄 필요 해상도로 축소 배치, 원본은 별도 보관 → 월 파일 용량 29MB에서 한 자릿수 MB로
- 병합 순서: 갑지 → 집계표 → 항목월 → 내역서(상세) → 사진대지 → 증빙

### 7.3 정확도 검증 (핵심 안전장치)

받은 실제 제출본 PDF 4종을 **정답지**로 삼는다. 프로그램이 생성한 PDF를 페이지별로 이미지화해
정답지와 겹쳐 **픽셀 차이율**을 계산하고, 기준선을 넘으면 실패로 처리한다. 서식을 수정할 때마다
자동으로 돌린다.

"육안 구분 불가"를 눈짐작이 아니라 수치로 확인하는 장치이며, B안의 유일한 약점을 막는다.

정답지 파일은 실제 현장·거래처 정보를 담고 있어 **저장소에 커밋하지 않는다.** 로컬 검증용
폴더에 두고 경로만 설정으로 관리한다.

## 8. 배포와 저장

- 단일 실행파일. 설치 없이 폴더에서 실행하며 USB 이동도 가능하다.
- 데이터는 `E:\CMP_FABLE` 아래 현장별 폴더에 쌓인다. 데이터베이스 파일 1개 + 증빙/사진 폴더
  구조로, 프로그램 없이 탐색기에서도 파일을 찾을 수 있다.
- 백업은 버튼 한 번으로 압축 파일 생성. USB·클라우드로 옮긴다.

## 10. 가정과 미결 사항

- 안전관리비 Ⅱ 내역서의 배율 93%는 내용 증가에 따른 수동 조정으로 보고, 재현 시에는 페이지
  자동 분할로 대체한다. 발주처가 배율까지 문제 삼은 적이 없다는 전제다.
- 집계표의 누계 공정율은 매월 수기 입력값을 그대로 인쇄한다. 현행 파일의 숨은 열 구조는
  승계하지 않는다.
- 항목 목록은 현행 제출본 기준으로 고정했다. 법령 개정 시 항목이 바뀌면 설정 갱신이 필요하다.
- 사진대지 캡션의 "위치"는 현행 제출본에서 `현장 내`가 반복 사용되나, 기본값 없이 수기 입력으로
  한다(사용자 결정).
