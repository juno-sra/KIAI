# SMP TBM 모듈 명세서

- 문서번호: SMP-MOD-TBM-001
- 상위 문서: SMP-ARCH-001 (`2026-09-16-smp-platform-architecture.md`)
- 작성일: 2026-09-16
- 상태: 초안 (검토 대기)

---

## 1. 모듈 개요

작업 전 안전미팅(TBM, Tool Box Meeting) 실시 사실과 그 내용을 기록하고, 일지 형태로
출력·보존하는 모듈이다.

| 항목 | 값 |
|---|---|
| 모듈 ID | `tbm` |
| 참조 공통 마스터 | `site`, `company`, `worker`, `workType`, `hazard` (읽기 전용) |
| 산출 문서 | TBM 일지(일자별), TBM 실시현황(월간 집계) |

## 2. 법적 근거 검토

### 2.1 TBM 자체를 직접 규정한 조문

**근거 확인 불가.**
산업안전보건법, 같은 법 시행령·시행규칙, 산업안전보건기준에 관한 규칙에서
"TBM" 또는 "작업 전 안전미팅"을 명칭으로 직접 규정한 조문은 확인되지 않는다.
TBM은 고용노동부·안전보건공단이 권장하는 현장 활동으로 운영되고 있다.

따라서 본 모듈은 **TBM 실시가 법정 의무라고 표시하지 않는다.**
다만 TBM에서 실제로 수행되는 행위는 아래 법정 업무와 내용상 겹치며, 그 범위에서만
근거를 표시한다.

### 2.2 TBM 수행 내용과 연결되는 법정 업무

| TBM 수행 내용 | 관련 법조문 | 비고 |
|---|---|---|
| 당일 작업의 유해·위험요인 확인 및 주지 | 산업안전보건기준에 관한 규칙 제35조제1항, 별표 2 (관리감독자의 유해·위험 방지 업무) | 관리감독자 직무 |
| 작업 시작 전 점검 | 산업안전보건기준에 관한 규칙 제35조제2항, 별표 3 (작업시작 전 점검사항) | 점검 대상 작업이 한정 열거됨 |
| 보호구 착용 지도·점검 | 산업안전보건기준에 관한 규칙 제32조 (보호구의 지급 등) | |
| 안전보건에 관한 교육 | 산업안전보건법 제29조, 같은 법 시행규칙 제26조·별표 4·별표 5 | 정기교육 시간 인정 여부는 아래 참조 |
| 위험성평가 결과의 근로자 공유 | 산업안전보건법 제36조제3항 | 실시 내용·결과를 근로자에게 알릴 의무 |
| 안전보건 관계 법령 의무이행 점검 체계 | 중대재해 처벌 등에 관한 법률 제4조제1항, 같은 법 시행령 제5조 | 경영책임자 의무 |
| 기록의 보존 | 산업안전보건법 제164조 | 서류별 보존기간 상이 |

### 2.3 미확정 쟁점

| 번호 | 쟁점 | 판단 |
|---|---|---|
| L1 | TBM 실시 기록이 산업안전보건법 제29조 정기교육 시간으로 인정되는지 | **근거 확인 불가** — 고용노동부 행정해석 확인 필요. 모듈은 "교육시간 자동 합산" 기능을 **제공하지 않는다** |
| L2 | TBM 일지의 법정 보존기간 | **근거 확인 불가** — 산업안전보건법 제164조의 보존 대상 서류 목록에 "TBM 일지"가 명시되어 있지 않다. 모듈 기본값은 **3년 보관**(제164조제1항 다수 항목의 보존기간에 맞춘 운영상 기본값)으로 하되, 화면에 "법정 보존기간 근거 확인 불가, 운영 기본값" 이라고 표시한다 |
| L3 | 전자 서명(태블릿 필기 서명)의 효력 | **근거 확인 불가** — 전자서명법상 효력 여부는 별도 법률 검토 필요. 모듈은 서명 이미지를 "참석 확인용 기록"으로만 표시한다 |

> **표시 원칙**: 화면과 출력물 어디에서도 "본 기록으로 법정 의무가 이행됨"이라고
> 표시하지 않는다. 법정 근거가 확인된 항목에만 조문을 병기하고, 나머지는
> "근거 확인 불가"로 표시한다.

## 3. 데이터 모델

### 3.1 집합체(Aggregate): TbmSession

```ts
interface TbmSession {
  id: string;                    // ULID
  siteId: string;

  /** 실시 일자 및 시각 */
  date: string;                  // YYYY-MM-DD
  startAt: string;               // HH:mm
  endAt: string;                 // HH:mm
  durationMinutes: number;       // 파생값

  /** 실시 장소 */
  location: string;

  /** 주관자 (관리감독자 또는 작업반장) */
  leader: {
    workerId: string;
    role: '관리감독자' | '작업반장' | '안전관리자' | '기타';
  };

  /** 대상 업체 및 공종 */
  companyId: string;
  workTypeId: string;

  /** 당일 작업 내용 */
  workDescription: string;

  /** 위험요인 및 안전대책 (1건 이상 필수) */
  hazards: TbmHazardItem[];

  /** 참석자 */
  attendees: TbmAttendee[];

  /** 작업 시작 전 점검 (해당 작업에 한함) */
  preWorkChecks?: PreWorkCheckResult[];

  /** 특이사항 */
  remarks?: string;

  /** 첨부 사진 (해시 참조) */
  photos: string[];

  status: 'draft' | 'confirmed';
  /** 확정 후 수정 시 사유 기재 필수 */
  amendments?: Amendment[];
}

interface TbmHazardItem {
  /** 공통 마스터의 표준 위험요인 참조 (없으면 직접 입력) */
  hazardId?: string;
  description: string;           // 위험요인
  control: string;               // 안전대책
  /** 위험성평가 연계 시 해당 평가 항목 ID */
  riskAssessmentRef?: string;
}

interface TbmAttendee {
  workerId: string;
  attended: boolean;
  /** 건강상태 확인 결과 */
  healthStatus: '이상없음' | '이상있음';
  healthNote?: string;           // healthStatus === '이상있음' 이면 필수
  /** 보호구 착용 확인 — 규칙 제32조 */
  ppeConfirmed: boolean;
  ppeNote?: string;
  /** 서명 이미지 해시 (선택) */
  signatureHash?: string;
}

interface PreWorkCheckResult {
  /** 산업안전보건기준에 관한 규칙 별표 3의 작업 구분 */
  workCategoryCode: string;
  /** 별표 3에 열거된 점검 항목 */
  itemCode: string;
  result: '양호' | '불량' | '해당없음';
  note?: string;
}

interface Amendment {
  at: string;
  actor: string;
  reason: string;                // 필수
  changedFields: string[];
}
```

### 3.2 이벤트

| 이벤트 타입 | 발생 시점 |
|---|---|
| `tbm.session.created` | 신규 TBM 작성 시작 |
| `tbm.session.updated` | 초안 수정 |
| `tbm.session.confirmed` | 확정 (이후 수정은 사유 필수) |
| `tbm.session.amended` | 확정 후 수정 |
| `tbm.attendee.marked` | 참석자 확인·건강상태·보호구 입력 |
| `tbm.photo.attached` | 사진 첨부 |
| `tbm.document.exported` | 일지 출력 |

`tbm.session.confirmed` 이후에는 `updated`를 허용하지 않고 `amended`만 허용한다.
`amended`는 `reason`이 비어 있으면 거부한다. 소급 수정 사실이 항상 남는다.

### 3.3 프로젝션(읽기 모델)

| 이름 | 용도 |
|---|---|
| `tbm_sessions` | 일자·업체·공종별 목록 조회 |
| `tbm_attendance_daily` | 일자별 참석 인원 집계 |
| `tbm_hazard_frequency` | 위험요인 빈도 — 반복 위험요인 식별 |
| `tbm_missing_days` | 작업일 중 TBM 미기록 일자 |

## 4. 화면 구성

### 4.1 화면 목록

| 화면 | 경로 | 내용 |
|---|---|---|
| TBM 목록 | `/tbm` | 월 달력 + 일자별 실시 현황. 미기록 작업일 표시 |
| TBM 작성 | `/tbm/new` | 5단계 입력 (아래 4.2) |
| TBM 상세 | `/tbm/:id` | 조회, 수정 이력, 출력 |
| 위험요인 사전 | `/tbm/hazards` | 공종별 표준 위험요인 조회 (공통 마스터, 읽기 전용) |
| 월간 현황 | `/tbm/monthly` | 업체별·공종별 실시 집계, 출력 |

### 4.2 작성 흐름 (현장 입력 속도 우선)

```
1. 기본정보   업체 / 공종 / 장소 / 시각      ← 전일 기록 불러오기 가능
2. 작업내용   당일 작업 서술
3. 위험요인   공종별 표준 사전에서 선택 + 직접 입력
              (위험성평가 모듈 연계 시 해당 평가 항목 자동 제시)
4. 참석자     업체 소속 인원 목록에서 체크
              건강상태 / 보호구 착용 일괄 "이상없음" 후 예외만 변경
5. 확인       요약 확인 → 확정
```

**"전일 기록 불러오기"의 안전장치**: 복사 관행이 만든 오류(전일 데이터 잔존)를
재현하지 않기 위해, 불러온 항목은 **시각적으로 구분 표시**하고 날짜·시각·참석자는
자동 복사 대상에서 제외한다. 위험요인은 복사하되 사용자가 각 항목을 명시적으로
확인해야 확정 단계로 넘어간다.

### 4.3 입력 검증

| 규칙 | 처리 |
|---|---|
| 위험요인 0건 | 확정 차단 |
| 참석자 0명 | 확정 차단 |
| 건강상태 '이상있음' + 비고 없음 | 확정 차단 |
| 미래 일자 | 확정 차단 |
| 작업 시작 시각 이후에 작성된 TBM | 경고 표시 (차단하지 않음, 사유 기록) |
| 동일 업체·동일 일자 중복 | 경고 후 허용 (교대 작업 가능) |

## 5. 출력물

### 5.1 TBM 일지 (일자별, A4 세로 1매)

```
┌────────────────────────────────────────────────┐
│           작업 전 안전미팅(TBM) 일지            │
├──────┬─────────────┬──────┬────────────────────┤
│ 현장 │             │ 일자 │  2026-09-16 (수)   │
├──────┼─────────────┼──────┼────────────────────┤
│ 업체 │             │ 시간 │  07:00 ~ 07:12     │
├──────┼─────────────┼──────┼────────────────────┤
│ 공종 │             │ 장소 │                    │
├──────┴─────────────┴──────┴────────────────────┤
│ 금일 작업 내용                                  │
├─────────────────┬──────────────────────────────┤
│ 위험요인         │ 안전대책                     │
├─────────────────┼──────────────────────────────┤
│ 1.              │                              │
│ 2.              │                              │
├─────────────────┴──────────────────────────────┤
│ 참석자 확인                                     │
│ 성명 / 직종 / 건강상태 / 보호구 / 서명          │
├────────────────────────────────────────────────┤
│ 특이사항                                        │
├────────────────────────────────────────────────┤
│ 주관자:              (서명)                     │
└────────────────────────────────────────────────┘
```

- 글꼴 **Pretendard** (본문 Regular, 표제 SemiBold)
- 참석자가 1매를 넘으면 2매째에 참석자만 이어서 인쇄하고 머리글을 반복한다
- 사진은 별지(사진대지)로 출력하며, 기존 법정경비 모듈의 사진대지 레이아웃 방식을 승계한다
- 각주에 근거 조문을 표기한다. 근거가 확인되지 않은 항목은 표기하지 않는다
  (허위 근거 표기 금지)

### 5.2 TBM 실시현황 (월간, A4 가로)

업체별·일자별 실시 여부 매트릭스 + 미실시 일자 표시.

## 6. 다른 모듈과의 연계 (후속)

| 연계 대상 | 방향 | 내용 |
|---|---|---|
| 위험성평가 모듈 | 위험성평가 → TBM | 해당 공종의 평가 결과를 위험요인 후보로 제시 (법 제36조제3항 공유 의무 대응) |
| 안전보건교육 모듈 | TBM → 교육 | **연계하지 않음.** 쟁점 L1 미해결이므로 교육시간 자동 인정 금지 |
| 순회점검 모듈 | TBM ↔ 점검 | TBM에서 식별한 위험요인의 조치 여부를 점검에서 확인 |
| 법정경비 모듈 | 무관 | 연계 없음 |

## 7. 1차 구현 범위 (Scope)

**포함**
- TbmSession 데이터 모델 및 이벤트
- 작성 5단계 화면, 목록, 상세
- 입력 검증
- TBM 일지 PDF 출력
- 동기화 폴더 기반 다중 사용자 조회·입력

**제외 (후속)**
- 태블릿 필기 서명 (쟁점 L3 미해결)
- 위험성평가 모듈 연계 (해당 모듈 미구현)
- 월간 현황 출력
- 모바일/웹 접근

## 8. 검토 요청 사항

| 번호 | 질문 |
|---|---|
| R1 | TBM 일지 양식에 현장에서 실제 사용 중인 서식이 있는가? 있다면 해당 파일을 정답지로 삼아 재현하겠다 |
| R2 | 참석자 서명을 종이 출력 후 수기로 받는가, 태블릿 입력을 원하는가? |
| R3 | 협력업체 직원도 SMP를 설치해 직접 입력하는가, 안전관리자가 일괄 입력하는가? |
| R4 | 위험요인 표준 사전을 처음부터 만들 것인가, 기존 위험성평가 자료를 가져올 것인가? |
