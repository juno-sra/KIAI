# SMP TBM 모듈 명세서

- 문서번호: SMP-MOD-TBM-001
- 상위 문서: SMP-ARCH-001 (`2026-09-16-smp-program-architecture.md`)
- 작성일: 2026-09-16
- 상태: 초안 (검토 대기)

---

## 1. 모듈 개요

작업 전 안전미팅(TBM, Tool Box Meeting) 실시 사실과 그 내용을 기록하고, 일지 형태로
출력·보존하는 모듈이다.

| 항목 | 값 |
|---|---|
| 모듈 ID | `daily` 모듈의 TBM 기능 (폴더: `SMP/daily/`) |
| 참조 공통 마스터 | `site`, `company`, `worker`, `workType`, `hazard` (읽기 전용) |
| 산출 문서 | TBM 일지(일자별), TBM 실시현황(월간 집계) |

---

## 2. 법적 근거 검토

### 2.1 TBM 자체를 직접 규정한 조문

**근거 확인 불가.**
산업안전보건법, 같은 법 시행령·시행규칙, 산업안전보건기준에 관한 규칙에서
"TBM" 또는 "작업 전 안전미팅"을 명칭으로 직접 규정한 조문은 확인되지 않는다.
TBM은 고용노동부·안전보건공단이 권장하는 현장 활동으로 운영되고 있다.

따라서 본 모듈은 **TBM 실시가 법정 의무라고 표시하지 않는다.**
다만 TBM에서 실제로 수행되는 행위는 아래 법정 업무와 내용상 겹치며, 그 범위에서만
근거를 표시한다.

### 2.2 TBM 수행 내용과 연결되는 법정 업무

| TBM 수행 내용 | 관련 법조문 | 비고 |
|---|---|---|
| 당일 작업의 유해·위험요인 확인 및 주지 | 산업안전보건기준에 관한 규칙 제35조제1항, 별표 2 (관리감독자의 유해·위험 방지 업무) | 관리감독자 직무 |
| 작업 시작 전 점검 | 산업안전보건기준에 관한 규칙 제35조제2항, 별표 3 (작업시작 전 점검사항) | 점검 대상 작업이 한정 열거됨 |
| 보호구 착용 지도·점검 | 산업안전보건기준에 관한 규칙 제32조 (보호구의 지급 등) | |
| 안전보건에 관한 교육 | 산업안전보건법 제29조, 같은 법 시행규칙 제26조·별표 4·별표 5 | 정기교육 시간 인정 여부는 아래 참조 |
| 위험성평가 결과의 근로자 공유 | 산업안전보건법 제36조제3항 | 실시 내용·결과를 근로자에게 알릴 의무 |
| 안전보건 관계 법령 의무이행 점검 체계 | 중대재해 처벌 등에 관한 법률 제4조제1항, 같은 법 시행령 제5조 | 경영책임자 의무 |
| 기록의 보존 | 산업안전보건법 제164조 | 서류별 보존기간 상이 |

### 2.3 미확정 쟁점

| 번호 | 쟁점 | 판단 |
|---|---|---|
| L1 | TBM 실시 기록이 산업안전보건법 제29조 정기교육 시간으로 인정되는지 | **해소.** 「안전보건교육규정」(고용노동부고시 제2023-63호, 2023. 12. 13. 시행) 개정으로 TBM이 안전보건 정기교육 시간으로 인정된다. 해당 반기 내 TBM 시간을 합산 인정하며 교육일지·작업일지 등 기록 방식도 인정된다. → 모듈은 **교육시간 합산 기능을 제공한다**(5.4·6절). 단 **고시 내 조문 번호는 미대조** |
| L2 | TBM 일지의 법정 보존기간 | **근거 확인 불가** — 산업안전보건법 제164조의 보존 대상 서류 목록에 "TBM 일지"가 명시되어 있지 않다. 모듈 기본값은 **3년 보관**(제164조제1항 다수 항목의 보존기간에 맞춘 운영상 기본값)으로 하되, 화면에 "법정 보존기간 근거 확인 불가, 운영 기본값" 이라고 표시한다 |
| L3 | 전자 서명(태블릿 필기 서명)의 효력 | **쟁점 제외.** 사용자가 종이 출력 후 수기 서명으로 확정했다(5.5절). 전자서명 기능을 구현하지 않으므로 검토 불요 |

> **표시 원칙**: 화면과 출력물 어디에서도 "본 기록으로 법정 의무가 이행됨"이라고
> 표시하지 않는다. 법정 근거가 확인된 항목에만 조문을 병기하고, 나머지는
> "근거 확인 불가"로 표시한다.

## 3. 데이터 모델

### 3.1 집합체(Aggregate): TbmSession

```ts
interface TbmSession {
  id: string;                    // ULID
  siteId: string;

  /** 실시 일자 및 시각 */
  date: string;                  // YYYY-MM-DD
  startAt: string;               // HH:mm
  endAt: string;                 // HH:mm
  durationMinutes: number;       // 파생값

  /** 실시 장소 */
  location: string;

  /** 주관자 (관리감독자 또는 작업반장) */
  leader: {
    workerId: string;
    role: '관리감독자' | '작업반장' | '안전관리자' | '기타';
  };

  /** 대상 업체 및 공종 */
  companyId: string;
  workTypeId: string;

  /** 서식 대응 항목 */
  workName: string;              // 작업명
  workDescription: string;       // 작업내용
  equipment: string[];           // 투입장비 (기종 + 장비번호)
  headcount: number;             // 출역인원

  /** 일일 안전교육 사항 — 건설기술진흥법 근거(조문 미대조) */
  dailyEducation: {
    method: boolean;             // 작업공법의 이해
    sequence: boolean;           // 시공상세도면에 따른 세부 시공순서
    precautions: boolean;        // 시공기술상의 주의사항
    note?: string;
  };

  /** 근로자 일일 안전교육사항 [정기안전교육] */
  regularEducationNote: string;

  /** 작업 후 종료 미팅 — 건의사항 및 사고사례 전파 */
  closingMeeting?: string;

  /** 결재란 — 현장 설정(9절)에서 정의한 칸을 그대로 따른다 */
  approvals?: ApprovalEntry[];

  /** 위험요인 및 안전대책 (1건 이상 필수) */
  hazards: TbmHazardItem[];

  /** 참석자 */
  attendees: TbmAttendee[];

  /** 작업 시작 전 점검 (해당 작업에 한함) */
  preWorkChecks?: PreWorkCheckResult[];

  /** 특이사항 */
  remarks?: string;

  /** 첨부 사진 (해시 참조) */
  photos: string[];

  status: 'draft' | 'confirmed';
  /** 확정 후 수정 시 사유 기재 필수 */
  amendments?: Amendment[];
}

interface TbmHazardItem {
  /** 위험요인 표준 사전 참조 (data/hazard-library/, 예: 'HZ-EXCV-003') */
  hazardId?: string;
  description: string;           // 잠재위험요소 (서식 용어)
  control: string;               // 대책 — 제거→대체→통제 순서 고려
  /** 서식의 '조치여부' 항목 */
  actionTaken: boolean;
  /** 미조치 시 대책 (actionTaken === false 이면 필수) */
  pendingAction?: string;
  /** 중점위험 여부 */
  isCritical: boolean;
  /** 위험성평가 연계 시 해당 평가 항목 ID */
  riskAssessmentRef?: string;
}

interface TbmAttendee {
  workerId: string;
  attended: boolean;
  /** 건강상태 확인 결과 */
  healthStatus: '이상없음' | '이상있음';
  healthNote?: string;           // healthStatus === '이상있음' 이면 필수
  /** 보호구 착용 확인 — 규칙 제32조 */
  ppeConfirmed: boolean;
  ppeNote?: string;
  /** 서명 이미지 해시 (선택) */
  signatureHash?: string;
}

interface PreWorkCheckResult {
  /** 산업안전보건기준에 관한 규칙 별표 3의 작업 구분 */
  workCategoryCode: string;
  /** 별표 3에 열거된 점검 항목 */
  itemCode: string;
  result: '양호' | '불량' | '해당없음';
  note?: string;
}

interface ApprovalEntry {
  /** 설정에 정의된 결재란 ID */
  slotId: string;
  /** 출력 시점의 직위명 스냅샷 — 이후 설정이 바뀌어도 과거 문서는 그대로 보존 */
  titleSnapshot: string;
  approvedBy?: string;
  approvedAt?: string;
}

interface Amendment {
  at: string;
  actor: string;
  reason: string;                // 필수
  changedFields: string[];
}
```

### 3.2 이벤트

| 이벤트 타입 | 발생 시점 |
|---|---|
| `tbm.session.created` | 신규 TBM 작성 시작 |
| `tbm.session.updated` | 초안 수정 |
| `tbm.session.confirmed` | 확정 (이후 수정은 사유 필수) |
| `tbm.session.amended` | 확정 후 수정 |
| `tbm.attendee.marked` | 참석자 확인·건강상태·보호구 입력 |
| `tbm.photo.attached` | 사진 첨부 |
| `tbm.document.exported` | 일지 출력 |

`tbm.session.confirmed` 이후에는 `updated`를 허용하지 않고 `amended`만 허용한다.
`amended`는 `reason`이 비어 있으면 거부한다. 소급 수정 사실이 항상 남는다.

### 3.3 프로젝션(읽기 모델)

| 이름 | 용도 |
|---|---|
| `tbm_sessions` | 일자·업체·공종별 목록 조회 |
| `tbm_attendance_daily` | 일자별 참석 인원 집계 |
| `tbm_hazard_frequency` | 위험요인 빈도 — 반복 위험요인 식별 |
| `tbm_missing_days` | 작업일 중 TBM 미기록 일자 |

## 4. 화면 구성

### 4.1 화면 목록

| 화면 | 경로 | 내용 |
|---|---|---|
| TBM 목록 | `/tbm` | 월 달력 + 일자별 실시 현황. 미기록 작업일 표시 |
| TBM 작성 | `/tbm/new` | 5단계 입력 (아래 4.2) |
| TBM 상세 | `/tbm/:id` | 조회, 수정 이력, 출력 |
| 위험요인 사전 | `/tbm/hazards` | 공종별 표준 위험요인 조회 (공통 마스터, 읽기 전용) |
| 월간 현황 | `/tbm/monthly` | 업체별·공종별 실시 집계, 출력 |

### 4.2 작성 흐름 (현장 입력 속도 우선)

```
1. 기본정보   업체 / 공종 / 장소 / 시각      ← 전일 기록 불러오기 가능
2. 작업내용   당일 작업 서술
3. 위험요인   공종별 표준 사전에서 선택 + 직접 입력
              (위험성평가 모듈 연계 시 해당 평가 항목 자동 제시)
4. 참석자     업체 소속 인원 목록에서 체크
              건강상태 / 보호구 착용 일괄 "이상없음" 후 예외만 변경
5. 확인       요약 확인 → 확정
```

**"전일 기록 불러오기"의 안전장치**: 복사 관행이 만든 오류(전일 데이터 잔존)를
재현하지 않기 위해, 불러온 항목은 **시각적으로 구분 표시**하고 날짜·시각·참석자는
자동 복사 대상에서 제외한다. 위험요인은 복사하되 사용자가 각 항목을 명시적으로
확인해야 확정 단계로 넘어간다.

### 4.3 입력 검증

| 규칙 | 처리 |
|---|---|
| 위험요인 0건 | 확정 차단 |
| 참석자 0명 | 확정 차단 |
| 건강상태 '이상있음' + 비고 없음 | 확정 차단 |
| 미래 일자 | 확정 차단 |
| 작업 시작 시각 이후에 작성된 TBM | 경고 표시 (차단하지 않음, 사유 기록) |
| 동일 업체·동일 일자 중복 | 경고 후 허용 (교대 작업 가능) |
| 조치여부 '아니오' + 미조치 대책 미기재 | 확정 차단 (서식에 '※미조치시 대책 기재' 명시) |
| 출역인원과 참석자 수 불일치 | 경고 표시 후 사유 기재 요구 |

## 5. 출력물 — 현장 실사용 서식 재현

사용자가 실제 사용 중인 서식 「TBM 및 일일안전교육 일지」를 정답지로 삼아 재현한다.
**TBM과 일일안전교육을 한 장에 담은 통합 서식**이다.

> 원본 PDF에는 현장명·업체명·근로자 실명·장비번호가 포함되어 있어 **저장소에
> 커밋하지 않는다**(이 저장소는 공개 상태). 아래는 치수와 구조만 추출한 것이다.

### 5.1 용지·여백 실측값

| 항목 | 실측값 |
|---|---|
| 용지 | A4 세로 (595 × 842 pt) |
| 좌측 여백 | 28.5 pt (약 10.0 mm) |
| 우측 경계 | 567.0 pt (우측 여백 약 9.9 mm) |
| 표 상단 시작 | 108.8 pt |
| 표 하단 끝 | 790.5 pt |
| 주요 세로 분할선 | 28.5 / 106.5 / 110.2 / 208.5 / 244.5 / 265.5 / 285.8 / 309.0 / 373.5 / 387.8 / 438.0 / 465.0 / 480.8 / 502.5 / 567.0 pt |
| 행 높이 | 약 19.5 pt 기본, 구간별 23.5~31.5 pt |
| 글꼴 | **Pretendard** (사용자 상시 지침) |

참석자 서명란은 **이름·서명 3열 구조**로, 페이지 하단 571.5 pt부터 790.5 pt까지
약 24 pt 간격의 행이 반복된다.

### 5.3 2면 — 사진대지

**여백은 사용자 지정값을 따른다 — 상단 25mm, 하단 20mm 고정.** 좌우는 실측값
46.5pt(약 16.4mm)를 쓴다. **제목을 뺀 나머지를 페이지당 장수로 균등 분할**하며,
사진 자리 높이는 고정값이 아니라 이 분할에서 계산된다.

**페이지당 2장** (사용자 지정). 설명표는 공사명·내용·날짜를 한 줄에 담아 사진
자리를 넓게 쓴다.

```
A4 세로 297mm
  상단 여백        25.0mm  (고정)
  ────────────────────────
  제목 영역        16.0mm  (실측)
  세트 1  사진    108.5mm  ┐
          설명표    9.0mm  ┘ 117.5mm
  세트 2  사진    108.5mm  ┐
          설명표    9.0mm  ┘ 117.5mm
  안전 여유         1.0mm
  ────────────────────────
  하단 여백        20.0mm  (고정)
```

**치수는 실제 인쇄 결과로 검증했다.** 계산만으로는 맞지 않는다.

- 제목 영역을 눈대중 18.2mm로 잡았으나 실제는 16.0mm였다. 차이만큼 사진이 작아진다.
- 설명표는 지정한 높이가 그대로 나오지 않는다. 셀 높이가 글자 크기와 안쪽 여백으로
  결정되기 때문이다. 실측값 9.0mm를 기준으로 삼는다.
- **안전 여유 1.0mm를 둔다.** 브라우저가 요소 높이를 반올림하므로 본문을 딱 맞추면
  넘친다. 실제로 본문이 0.06mm 초과해 **마지막 설명표가 통째로 사라진 일이 있었다.**
  계산상으로는 아무 문제가 없어 보였다.

검증은 `npm run verify:print` 로 실행한다. 브라우저로 렌더링해 요소 높이를 재고,
PDF로 뽑아 면 수와 여백을 잰다.

설명표는 **공사명 · 내용 · 날짜를 한 줄**에 담는다. 날짜는 `2026-09-17 (목)` 형식으로
짧게 적고, 긴 현장명이 줄을 밀어내지 않도록 넘치면 말줄임으로 처리한다.

여백이나 페이지당 장수를 바꾸면 사진 크기가 자동으로 따라간다. 한 면의 사진들은
항상 같은 크기다.

**사진 높이가 30mm 미만이 되는 설정은 거부한다.** 자리가 0보다 크기만 하면 통과시키면
한 면에 10장을 넣어 11mm짜리 사진을 만드는 설정도 지나간다. 그 크기로는 현장 상황을
확인할 수 없어 사진대지의 목적을 잃는다. 현재 여백 기준으로 최대 6장까지 가능하나, 기본값은 2장이다.

| 항목 | 값 | 출처 |
|---|---|---|
| 상단 여백 | 25.0 mm | 사용자 지정 |
| 하단 여백 | 20.0 mm | 사용자 지정 |
| 좌우 여백 | 16.4 mm | 실측 46.5pt |
| 인쇄 폭 | 177.3 mm | 실측 502.5pt |
| 페이지당 사진 | 2장 | 사용자 지정 |
| 제목 영역 | 16.0 mm | **실측** |
| 사진 자리 | 108.5 mm | 계산 |
| 설명표 | 9.0 mm (1행) | **실측** |
| 안전 여유 | 1.0 mm | **실측 근거** |
| 사진 상하 여백 | 5 px | 사용자 지정 |
| 사진 최소 높이 | 30 mm | 운영 기준 |

사진이 3장 이상이면 2장씩 나눠 면을 늘리고, 부제에 `(1/2)` 형식으로 면 번호를,
각 사진 좌상단에 일련번호를 붙인다. 한 면으로 끝나거나 한 장뿐이면 번호를 붙이지
않는다.

**사진은 축소본을 쓴다.** 실측 확인 결과 원본 4032×3024(2.5MB)가 긴 변 1600px
축소본에서 446KB가 되어, 설계에서 정한 약 500KB 기준과 맞는다. 인쇄 품질에
충분하며 동기화 부담이 크게 준다. 원본은 증거로 함께 보관한다.

**사진은 가로·세로 어느 쪽이든 높이가 같다** (사용자 지정). 칸을 꽉 채우고
(`object-fit: cover`) 넘치는 부분은 잘라낸다. 비율은 유지하므로 찌그러지지 않는다.
높이가 제각각이면 인쇄물이 가지런하지 않다.

**대신 가로로 매우 긴 사진이나 세로로 매우 긴 사진은 좌우 또는 상하가 잘린다.**
중앙을 기준으로 자르므로 가장자리 정보가 필요한 사진은 촬영 단계에서 여유를 두어야
한다.

사진 상하에 5px 여백을 두어 테두리에 딱 붙지 않게 한다.

**사진이 빠진 경우 조용히 건너뛰지 않는다.** 첨부는 있는데 파일을 찾지 못하면
빈 자리에 「사진 없음」과 해시 앞 8자를 적는다. 몇 장이 빠졌는지 알 수 없으면
서류를 제출한 뒤에야 발견하게 된다.

### 5.4 서식에 기재된 법적 근거

| 구역 | 서식 기재 근거 | 검증 상태 |
|---|---|---|
| 일일 안전교육 사항 | 건설기술진흥법 제65조, 같은 법 시행령 제103조 | **조문 미대조** — 원문 확인 필요 |
| 근로자 일일 안전교육사항 | 고용노동부고시 제2023-63호, 1일 1회 5~10분의 정기안전교육 인정 | 고시 존재 확인. **고시 내 조문 번호는 미대조** |

### 5.5 서명 방식

**종이 출력 후 수기 서명**으로 확정(사용자 지정). 태블릿 필기 서명은 구현하지 않는다.

- SMP는 참석자 성명이 인쇄된 서명란을 포함해 출력한다
- 서명을 받은 종이는 스캔하여 해당 TBM 기록에 첨부할 수 있다
- 첨부 스캔본은 `attachments/`에 내용해시 파일명으로 보관한다

이에 따라 쟁점 L3(전자서명 효력)은 **본 모듈의 쟁점에서 제외**한다.

## 6. 다른 모듈과의 연계 (후속)

| 연계 대상 | 방향 | 내용 |
|---|---|---|
| 위험성평가 모듈 | 위험성평가 → TBM | 해당 공종의 평가 결과를 위험요인 후보로 제시 (법 제36조제3항 공유 의무 대응) |
| 교육훈련 모듈 | TBM → 교육 | **연계한다.** 확정된 TBM의 실시 시간을 해당 반기 정기교육 시간에 합산한다 (고용노동부고시 제2023-63호). 합산 근거와 원본 TBM 기록을 추적 가능하게 남긴다 |
| 순회점검 모듈 | TBM ↔ 점검 | TBM에서 식별한 위험요인의 조치 여부를 점검에서 확인 |
| 법정경비 모듈 | 무관 | 연계 없음 |

## 6-1. 권한

본 기능의 데이터는 `SMP/daily/` 폴더에 저장되며, **일상활동 담당 작성자와 관리자에게만**
클라우드 공유된다. 타 업무 담당자는 이 폴더를 공유받지 못하므로 접근할 수 없다.
상세는 SMP-ARCH-002(`2026-09-16-smp-access-control.md`) 참조.

| 역할 | 본 기능에서의 권한 |
|---|---|
| 관리자 (안전관리자) | 전체 조회·작성·수정·출력, 인원 명부 배포 |
| 작성자 (일상활동 담당) | 작성·확정·출력. 같은 모듈 담당자끼리는 서로의 기록이 보인다 |
| 열람자 | 조회·출력만 |

참석자 명부는 `SMP/daily/roster.json`(AES-256-GCM 암호화)을 사용한다. 관리자가 TBM 대상 인원만 배포하며,
전체 인원 명부는 이 폴더에 두지 않는다 (개인정보 보호법 제3조제1항·제6항, 제29조).

## 8. 결재란 설정

결재란은 현장·회사마다 다르므로 **별도 설정 화면에서 증감**할 수 있게 한다
(사용자 지정). 코드에 고정하지 않는다.

### 8.1 설정 위치와 적용 범위

- 화면: `설정 > 문서 > 결재란`
- 저장: `SMP/_공통/document-settings.json` (관리자만 편집)
- 적용: 모듈별로 서로 다른 결재란을 쓸 수 있도록 **문서 종류별로** 설정한다
  (예: TBM 일지 3칸, 순회점검일지 2칸)

```jsonc
{
  "approvalBlocks": {
    "daily.tbm": {
      "label": "담당자",
      "position": "top-right",
      "slots": [
        { "id": "slot_1", "title": "공사팀", "order": 1, "required": false },
        { "id": "slot_2", "title": "안전팀", "order": 2, "required": false },
        { "id": "slot_3", "title": "현장대리인", "order": 3, "required": false }
      ]
    }
  }
}
```

### 8.2 설정 화면 동작

| 동작 | 내용 |
|---|---|
| 칸 추가 | 최대 6칸까지. 초과 시 A4 폭을 넘어 인쇄가 깨지므로 제한한다 |
| 칸 삭제 | 최소 1칸은 남긴다. 삭제 시 기존 문서 영향 여부를 경고 |
| 직위명 수정 | 자유 입력 (예: 공사팀 / 안전팀 / 현장대리인 / 감리 / 발주처) |
| 순서 변경 | 드래그로 좌→우 순서 조정 |
| 위치 | 우측 상단 / 좌측 상단 / 하단 중 선택 |
| 미리보기 | 설정 즉시 A4 출력 미리보기에 반영 |

### 8.3 과거 문서 보존

결재란 설정을 바꿔도 **이미 확정된 문서의 결재란은 바뀌지 않는다.**
확정 시점의 직위명을 `titleSnapshot`으로 문서에 함께 저장하기 때문이다.

이는 산업안전보건법 제164조에 따른 보존 서류가 작성 당시 형태를 유지해야 한다는
요구에 대응한다. (다만 전자적 보존의 요건 충족 여부는 **근거 확인 불가** — 별도 검토 필요)

### 8.4 출력 시 폭 배분

결재란 전체 폭은 고정하고 칸 수로 균등 분할한다. 실측 서식 기준 결재란 구역은
우측 상단 373.5 ~ 567.0 pt (약 193.5 pt)이며, 3칸일 때 칸당 약 64.5 pt다.
