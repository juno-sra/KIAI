## 1. 요구사항

각 작업자는 아이디별 권한에 따라 서로 다른 업무를 수행하며, **다른 작업자가 어떤 업무를
하는지 알 수 없어야 한다.** 화면에서 가리는 수준이 아니라 실제로 접근이 차단되어야 한다.

---

## 2. 왜 앱 내부 권한만으로는 부족한가

SMP는 서버가 없고 클라우드 동기화 폴더를 저장소로 쓴다. 이 구조에서 앱이 화면을 가려도,
**동기화 폴더 접근 권한을 가진 사람은 탐색기에서 `.jsonl` 파일을 직접 열어 전부 읽을 수
있다.** 앱 내 역할 설정은 프로그램을 우회하면 무력하다.

따라서 **신뢰 경계를 앱이 아니라 클라우드 폴더 공유 권한에 둔다.**

| 계층 | 역할 | 우회 가능성 |
|---|---|---|
| 클라우드 폴더 공유 권한 | **실제 차단선** | 불가 (OneDrive/Google Drive가 강제) |
| 앱 내 역할·화면 제어 | 오조작 방지, 편의 | 가능 (파일 직접 열람) |

이 설계는 개인정보 보호법 제29조(안전조치의무) 및 같은 법 시행령 제30조제1항제2호
(개인정보에 대한 접근 권한의 제한 조치), 「개인정보의 안전성 확보조치 기준」
(개인정보보호위원회 고시) 제5조(접근 권한의 관리)·제6조(접근통제)의 취지에 따른다.

> 고시는 개정이 잦으므로, 구현 시점의 시행 중인 고시 조문을 재확인해야 한다.
> 본 문서의 고시 조문 번호는 작성 시점 기준이다.

## 3. 폴더 구조 (모듈별 분리)

```
<클라우드 루트>/SMP/
  _공통/                         ← 전원 읽기 / 관리자만 쓰기
    manifest.json                현장 식별자, 스키마 버전, 모듈 목록
    master/
      site.json                  현장 정보
      companies.json             업체 (상호, 공종, 계약기간)
      worktypes.json             공종 분류
      hazards.json               표준 위험요인 사전
    members.json                 사용자 등록부 (아이디, 표시명, 역할, 담당 모듈)

  tbm/                           ← TBM 담당 작성자 + 관리자
    events/<deviceId>.jsonl
    attachments/<yyyy>/<mm>/<sha256>.<ext>
    roster.json                  관리자가 배포한 TBM 대상 인원 명부

  education/                     ← 교육 담당 작성자 + 관리자
  inspection/                    ← 점검 담당 작성자 + 관리자
  legal-cost/                    ← 경비 담당 작성자 + 관리자
    …각 모듈 동일 구조

  _관리자/                       ← 안전관리자 본인만
    master/workers.json          전체 인원 명부 (개인정보 원본)
    exports/                     취합 출력물
    audit/                       권한 점검 이력
```

### 3.1 공유 권한 배정

| 폴더 | 관리자 | 해당 모듈 작성자 | 해당 모듈 열람자 | 타 모듈 담당자 |
|---|---|---|---|---|
| `_공통/` | 편집 | 보기 | 보기 | 보기 |
| `tbm/` | 편집 | **편집** | 보기 | **공유 안 함** |
| `education/` | 편집 | 편집 | 보기 | **공유 안 함** |
| `_관리자/` | 편집 | **공유 안 함** | **공유 안 함** | **공유 안 함** |

타 모듈 담당자는 해당 폴더를 **애초에 공유받지 못하므로** 앱을 우회해도 존재조차 확인할 수
없다. 요구사항 "다른 작업자의 업무가 무엇인지도 모른다"가 이 지점에서 충족된다.

### 3.2 개인정보 최소 배포

전체 인원 명부(`workers.json`)는 `_공통/`이 아니라 `_관리자/`에 둔다.
각 모듈 폴더의 `roster.json`에는 **해당 모듈 수행에 필요한 인원만** 관리자가 배포한다.

- 근거: 개인정보 보호법 제3조제1항(최소한의 개인정보 수집), 제6항, 제29조
- 주민등록번호는 저장하지 않는다 (개인정보 보호법 제24조의2)
- `roster.json`은 성명·소속업체·직종·생년월일까지로 한정한다

## 4. 역할 정의

| 역할 | 권한 | 대상 |
|---|---|---|
| **관리자** | 전체 폴더 접근. 사용자 등록·역할 배정, 마스터 관리, 명부 배포, 전체 취합·출력 | 안전관리자 본인 1인 |
| **작성자** | 담당 모듈 폴더에 기록 작성·수정. 공통 마스터 읽기 | 모듈별 담당자 |
| **열람자** | 담당 모듈 폴더 읽기 전용 | 확인·결재만 하는 인원 |

**전체 현황 조회 화면은 관리자 역할에만 나타난다.** 작성자·열람자 화면에는 담당 모듈만
표시되며, 좌측 내비게이션에 타 모듈 항목 자체가 생성되지 않는다.

### 4.1 모듈 내부에서의 가시성

분리 단위가 모듈이므로, **같은 모듈을 담당하는 작성자끼리는 서로의 기록을 본다.**
(예: TBM 작성자 2명은 서로의 TBM 일지를 조회 가능)
업체별·개인별로 더 잘게 나누려면 폴더를 그만큼 더 쪼개야 하며, 공유 설정 관리 부담이
비례해 증가한다. 1차 범위에서는 모듈 단위로 확정한다.

## 5. 사용자 등록 및 식별

서버가 없으므로 **인증(authentication)은 불가능하다.** 아이디는 식별 수단이다.

```jsonc
// _공통/members.json — 관리자만 편집
{
  "members": [
    {
      "userId": "u_kim",
      "displayName": "김○○",
      "role": "writer",
      "modules": ["tbm"],
      "registeredAt": "2026-09-16T09:00:00+09:00",
      "registeredBy": "u_admin"
    }
  ]
}
```

- 최초 실행 시 사용자가 자기 `userId`를 선택하고, 기기가 `deviceId`를 발급받아 등록한다.
- 등록되지 않은 `userId`로는 실행되지 않는다.
- **이 선택은 자기신고다.** 타인의 `userId`를 고를 수 있다. 실제 차단은 4항이 아니라
  3.1항의 폴더 공유 권한이 수행한다.
- 기록의 `actor`에는 `userId`와 `deviceId`를 함께 남긴다.

## 6. 권한 점검 (Permission Probe)

앱 시작 시 선언된 역할과 **실제 파일시스템 권한이 일치하는지 검사**한다.

```
각 모듈 폴더에 대해:
  읽기 가능?  → 디렉터리 목록 조회
  쓰기 가능?  → .probe 임시 파일 생성·삭제
결과를 members.json의 선언과 대조
```

| 상황 | 처리 |
|---|---|
| 선언: 작성자 / 실제: 읽기만 | 경고 표시, 해당 모듈 읽기 전용 동작. 관리자에게 공유 설정 재확인 안내 |
| 선언: 담당 아님 / 실제: 쓰기 가능 | **경고 표시** — 클라우드 공유 설정이 잘못되어 격리가 깨진 상태. 화면에는 계속 숨기되, 사용자에게 "설정 점검 필요"를 알린다 |
| `_관리자/` 접근 가능 + 역할이 관리자 아님 | 위와 동일하게 경고 |

점검 결과는 `_관리자/audit/`에 기록한다(관리자 기기에서만).

> **프로그램의 한계 명시**: 클라우드 폴더 공유 설정은 사람이 OneDrive/Google Drive에서
> 직접 수행해야 한다. SMP는 설정을 대신 변경할 수 없고, 잘못된 설정을 **탐지해 알릴 수만**
> 있다. 이 사실을 초기 설정 화면에 표시한다.

## 7. 관리자 초기 설정 마법사

격리가 사람의 폴더 공유 설정에 달려 있으므로, 관리자에게 절차를 안내한다.

```
1. 클라우드 루트에 SMP/ 폴더 생성 (앱이 수행)
2. 모듈 선택 — 이 현장에서 사용할 모듈 체크
3. 사용자 등록 — 아이디, 표시명, 역할, 담당 모듈
4. 공유 설정 안내 — 사용자별로 공유해야 할 폴더 목록을 표로 출력
   "김○○ → SMP/_공통(보기), SMP/tbm(편집)"
   이 표를 보고 관리자가 클라우드에서 직접 공유 설정
5. 점검 — 각 사용자 기기에서 앱 실행 후 권한 점검 결과를 관리자가 확인
```

4단계 표는 인쇄·저장이 가능해야 한다.

## 8. 설계 한계 (반드시 고지)

| 한계 | 내용 |
|---|---|
| 인증 없음 | 아이디는 식별일 뿐 본인 확인이 아니다. 차단은 클라우드 계정 권한이 수행한다 |
| 설정 의존 | 폴더 공유 설정이 잘못되면 격리가 깨진다. SMP는 탐지만 가능하다 |
| 모듈 단위 | 같은 모듈 담당자끼리는 서로의 기록이 보인다 |
| 관리자 기기 | 관리자 PC가 전체 데이터에 접근하므로, 해당 PC 분실·유출 시 전체가 노출된다. 디스크 암호화(BitLocker) 사용을 권고한다 |
| 자체 암호화 없음 | 클라우드 제공자의 암호화에 의존한다. 1차 범위 외 |
