# SMP 윈도우 PC에서 돌려보기

현재 단계에서는 **화면(창)이 없습니다.** 공통 기반 로직만 만들어진 상태이며,
Electron 셸과 화면은 다음 단계입니다.

대신 **동작 시연 스크립트**로 핵심 동작을 눈으로 확인할 수 있습니다. 실제로
폴더와 파일이 만들어지므로 탐색기와 메모장으로 직접 열어 보실 수 있습니다.

---

## 1. 준비 — Node.js 설치

1. https://nodejs.org 접속
2. **LTS 버전**(권장) 내려받아 설치 — 설치 중 기본값 그대로 두면 됩니다
3. 설치 후 확인

명령 프롬프트를 엽니다. (윈도우 키 → `cmd` 입력 → 엔터)

```
node -v
```

`v22.x.x` 같은 숫자가 나오면 됩니다. **v22 이상**이어야 합니다.

> 숫자가 안 나오고 오류가 나면, 명령 프롬프트를 닫고 다시 열어 보십시오.

---

## 2. 소스 내려받기

### 방법 A — ZIP으로 (Git을 모르셔도 됩니다)

1. https://github.com/juno-sra/KIAI 접속
2. 브랜치를 `claude/smc-module-program-e74kpw` 로 변경
3. 초록색 **Code** 버튼 → **Download ZIP**
4. 내려받은 파일을 `C:\SMP` 같은 곳에 풀기

### 방법 B — Git이 있으시면

```
cd C:\
git clone https://github.com/juno-sra/KIAI.git
cd KIAI
git checkout claude/smc-module-program-e74kpw
```

---

## 3. 설치 및 시험

명령 프롬프트에서 압축을 푼 폴더의 `apps\smp` 로 이동합니다.

```
cd C:\SMP\KIAI\apps\smp
```

필요한 개발 도구를 내려받습니다. (처음 한 번만, 1~2분 걸립니다)

```
npm install
```

시험을 돌립니다.

```
npm test
```

**이렇게 나오면 정상입니다.**

```
 Test Files  10 passed (10)
      Tests  90 passed | 2 skipped (92)
```

> `2 skipped`는 정상입니다. 리눅스 전용 권한 시험이라 윈도우에서는 건너뜁니다.

---

## 4. 동작 시연 보기

```
npm run demo
```

**바탕화면에 `SMP-데모` 폴더**가 만들어지고, 화면에 7단계가 순서대로 나옵니다.

| 단계 | 보실 내용 |
|---|---|
| 1 | 현장 초기화 — 모듈별 폴더가 나뉘는 구조 |
| 2 | TBM 기록이 한 줄씩 쌓이는 모습 |
| 3 | **두 PC가 같은 기록을 고쳤을 때** 어느 쪽이 남고 어느 쪽이 밀려나는지 |
| 4 | **OneDrive 동기화 중 파일이 잘렸을 때** 어떻게 견디는지 |
| 5 | **개인정보 암호화** — 명부는 잠기고 기록은 평문인 것 |
| 6 | **권한 점검** — 공유 설정이 잘못된 것을 찾아내는 모습 |
| 7 | **결재란** 칸을 늘리고 줄이는 것 |

---

## 5. 직접 열어서 확인하기

시연이 끝나면 **바탕화면 `SMP-데모\SMP` 폴더**를 탐색기로 열어 보십시오.

### 꼭 열어 보실 파일

**① 기록 파일 — 메모장으로 열립니다**

```
daily\events\dev_현장사무실PC.jsonl
```

- 한 줄에 기록 하나씩 쌓여 있습니다
- 기존 줄을 고치지 않고 **덧붙이기만** 하므로, 누가 언제 무엇을 했는지 그대로 남습니다
- **성명이 없고 `w_001` 같은 ID만 있는 것**을 확인해 보십시오

**② 인원 명부 — 열어도 안 읽힙니다**

```
_관리자\master\workers.json
```

메모장으로 열면 깨진 글자만 나옵니다. **암호화되어 있기 때문입니다.**
이것이 이름이 유출되지 않는 이유입니다.

**③ 격리된 깨진 줄**

```
daily\events\.quarantine\broken-....jsonl
```

형식이 깨진 기록을 조용히 버리지 않고 여기 남깁니다.

> `.quarantine` 폴더가 안 보이면 탐색기에서
> **보기 → 표시 → 숨긴 항목**을 켜십시오.

---

## 6. OneDrive에서 실제로 시험하기

가장 중요한 확인입니다. **실제 OneDrive 폴더를 지정**해 보십시오.

```
npm run build
node tools\demo.mjs "C:\Users\사용자이름\OneDrive\SMP시험"
```

> `사용자이름` 부분은 본인 윈도우 계정 이름으로 바꾸십시오.
> 탐색기 주소창에서 OneDrive 폴더 경로를 복사해 쓰시면 정확합니다.

실행 후 확인할 것:

1. OneDrive 아이콘에 **동기화 완료 표시(초록 체크)** 가 뜨는지
2. 웹 브라우저에서 OneDrive에 접속했을 때 **파일이 올라가 있는지**
3. **충돌 사본**(`...의 충돌 사본.jsonl`)이 생기지 **않는지**

3번이 핵심입니다. 기기마다 자기 파일에만 쓰도록 설계했으므로 충돌 사본이
생기면 안 됩니다. 만약 생긴다면 알려 주십시오 — 설계에 문제가 있다는 뜻입니다.

---

## 7. 다시 해보고 싶으면

`npm run demo` 를 다시 실행하면 됩니다. 이전 시연 폴더는 자동으로 지워지고
새로 만들어집니다.

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| `node`를 찾을 수 없다 | Node.js 설치 후 명령 프롬프트를 **닫았다 다시** 여십시오 |
| `npm install` 이 멈춘다 | 회사 방화벽일 수 있습니다. 개인 네트워크에서 시도해 보십시오 |
| 한글이 깨져 보인다 | 명령 프롬프트에서 `chcp 65001` 입력 후 다시 실행 |
| 시험이 실패한다 | 실패 내용을 그대로 알려 주십시오 |
